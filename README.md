# pair-wise-yf-50 灾后需求评估与任务分派离线前端

源提示词摘要：评估员在弱网环境离线记录家庭需求、特殊照护和现场说明，团队负责人合并重复记录、分派复核任务并追踪进展；多人修改同一记录时提供字段级冲突展示，不静默覆盖。

## 技术栈

Nuxt3（SPA）、TypeScript、Naive UI、Pinia、Axios、VueUse、VeeValidate、Zod、Vue I18n。

## 本地运行

```bash
npm install
npm run dev      # 开发：http://localhost:62015
npm run build    # 生产构建
npm test         # 同步引擎逻辑测试（74 项断言）
npm run typecheck
```

## 续作批次（断网回站补传）设计

评估设备断网期间继续登记/修改，回站后与“队部回站补传终端”（`utils/sync.ts` 中模拟）对账：

- **每笔带编号、设备、基线**：批次 `batchSeq` + 笔内流水 `seq`、设备编号 `PAD-xxxx`、家庭逐字段基线 `base`（页面显示基线短哈希）与修订号 `rev`。
- **重发只拿第一次结果**：服务端按批次号缓存结果；同批次重放返回 `duplicate=true` 和首次结果，写入幂等（家庭/任务/合并均带 `clientId` 去重），不产生副本、不覆盖同事刚改的内容。
- **失败只重试没收下的部分**：弱网丢包的笔返回 `error` 且**不缓存**，下一批只包含仍未 `ack` 的操作；已收下的笔不会再发。
- **字段级三方合并**（`utils/merge.ts`）：基线（共同祖先）/本机/对端逐字段比较。只有一边改过 → 自动接收；**同一字段两边都改过 → 两版都留下**，进入冲突面板，提供“采用本机 / 采用对端 / 两版都保留”，绝不静默覆盖。
- **重复记录合并**：可选保留记录，来源记录在对端置墓碑；现场复核任务（含已完成，完成态不可回退）与待同步操作整体转到保留记录；需求取并集。对端也独立合并时，拉取墓碑本地跟随，不二次合并。
- **未定案不推进家庭状态**：存在“待处理/保留两版”字段冲突、属于未处理重复组、或有未完成现场任务时，家庭状态不自动落定；任务全部闭环且无阻碍后才收敛为“已完成”。

界面上“同步队列”面板可勾选“模拟弱网：下一批第 1 笔对端收不到”观察续作行为；批次台账记录每批编号、设备、新收下/冲突/未收下/重放命中数。

## 代码结构

- `stores/assessment.ts` — Pinia store：离线队列、批次构建/落账、冲突定案、状态门禁、本地持久化
- `utils/sync.ts` — 回站对端模拟：幂等批次、字段验收、墓碑合并账本、任务完成定案
- `utils/merge.ts` — 纯函数三方合并（含墓碑收编、任务重挂）
- `utils/seed.ts` — 双方共享基线种子数据
- `tests/sync-flow.mjs` / `tests/store-flow.mjs` — 引擎与整链路集成测试
